# command-interface-adaptor-impl

## 概要

このモジュールはコマンド側のインターフェースアダプターの実装を提供します。

## 主な実装

- GroupChatRepository
    - イベントストアを利用したグループチャットを永続化するためのリポジトリ実装

## 利用する DynamoDB のテーブル構成

ESA v5 の DynamoDB ストレージは、`journal`、`snapshot`、`head` の 3 テーブルを使います。
いずれもパーティションキーは `aid`（`${型名}-${集約ID}`）です。論理シャードや
ハッシュによるキー変換は行いません。

| テーブル | ソートキー | GSI | Streams | 役割 |
|:--|:--|:--|:--|:--|
| `journal` | `seq_nr` (N) | なし | 無効 | イベントの追記ログ |
| `snapshot` | `skey` (N)。現在値は 0、履歴は `seq_nr` | `(aid, active_history_seq_nr)`、KEYS_ONLY | 無効 | 集約状態のキャッシュと履歴 |
| `head` | なし | なし | NEW_IMAGE | 集約ごとの最新 `seq_nr` と直近イベント |

3 テーブルには、同じ `store_id` と `layout_version=1` を持つ設定項目を 1 件ずつ置きます。
ジャーナルは `seq_nr=0`、スナップショットは `skey=0`、ヘッドは `aid="__config__"` です。
ストアは生成時に 3 件を強整合で読み、一致しなければ設定エラーにします。

### イベントの属性

イベントのメタデータは封筒で運び、payload には埋め込みません。

| 属性 | 型 | 内容 |
|:--|:--|:--|
| `aid` | S | 集約 ID。パーティションキー |
| `seq_nr` | N | イベントの通し番号。journal のソートキー |
| `occurred_at` | N | Unix エポックからのナノ秒 |
| `manifest` | S | 自由文字列。省略時は空文字列 |
| `payload` | B | 直列化したイベント本体 |

ヘッド項目はこれに加えて `type_name`（型名）と `events`（直前の書き込みで追記した
イベントのリスト）を持ちます。

イベントの `manifest` は `<イベント型名>@<スキーマ版>`（例: `GroupChatCreated@1`）、
スナップショットの `manifest` は `GroupChat@1` です。payload はイベント型の判別子
`type` とドメインのデータだけを含み、集約 ID、`seq_nr`、`occurred_at`、`manifest`
は含みません。スナップショットの payload は集約状態で、旧来の `version` 属性は
持ちません。

### イベント及びスナップショットの書き込み

1. 集約にてコマンドが受理されると、最新の `seq_nr` が付与されたイベントが生成されます。
2. イベントは 1 つの `TransactWriteItems` で journal と head に書きます。スナップショットを
   保存するときは snapshot も同じトランザクションに含めます。
3. 新しい集約は head が存在しないことを条件にし、更新は `head.seq_nr = event.seq_nr - 1`
   を条件にします。重複した `seq_nr` や飛びは書き込み時に失敗します。

### イベント及びスナップショットを使って集約をリプレイする

1. 集約 ID を指定して、head の `seq_nr` と現在のスナップショットを `BatchGetItem` で
   強整合読み取りします。
2. スナップショットがなければ journal の先頭から、あればスナップショットの
   `seq_nr + 1` 以降のイベントを journal から強整合で読みます。
3. 読み込んだイベントをスナップショットに適用することで、最新の集約状態を取得します。

### 変更フィード

変更フィードは head テーブルの Streams だけを使います。journal は 1 イベント 1 項目なので、
同じ集約のイベントでも順序を保証しません。購読側は `(aid, seq_nr)` で重複を捨て、
`seq_nr` の飛びを見つけたら journal から補います。
